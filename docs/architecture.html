Architecture Reference -- AI-Enhanced Threat Detection and Automated Security Triage

Terraform AWS GuardDuty Security Hub Bedrock EventBridge Lambda SNS

Executive Summary

This module deploys AWS GuardDuty with AI-enhanced threat detection. It provisions a GuardDuty detector with all six protection plans (S3, EKS, Malware, RDS, Lambda, Runtime Monitoring), an AI-powered triage pipeline that uses Amazon Bedrock (Claude 3 Sonnet) to analyze and enrich security findings, EventBridge routing for real-time event processing, SNS alerting with formatted notifications, Security Hub integration for centralized security posture, S3-based findings archival with Glacier lifecycle, and multi-account member management. Custom filter criteria allow auto-archiving of known benign patterns.

Component Breakdown

GuardDuty Detector

  • Detector -- Core threat detection engine with configurable publishing frequency (15min/1hr/6hr)
  • S3 Protection -- Monitors S3 data access patterns
  • EKS Protection -- Kubernetes audit log analysis
  • Malware Protection -- EBS volume scanning on EC2 findings
  • RDS Protection -- Login activity monitoring
  • Lambda Protection -- Network activity monitoring
  • Runtime Monitoring -- Agent management for EKS, ECS Fargate, EC2

Multi-Account

  • Member Accounts -- Invite and manage member accounts with email notifications
  • Custom Filters -- Auto-archive benign patterns with field-level criteria

AI Triage Pipeline

  • EventBridge Rule -- Captures all "GuardDuty Finding" events
  • AI Triage Lambda -- Python 3.12 function (512MB, 120s timeout)
  • Amazon Bedrock -- Invokes Claude 3 Sonnet for finding analysis and enrichment
  • SNS Enriched Alerts -- AI-analyzed findings published to SNS

Alerting & Archival

  • SNS Topic -- KMS-encrypted; formatted input transformer for severity/title/description
  • S3 Findings Archive -- Versioned, encrypted bucket with Glacier lifecycle
  • Security Hub -- Centralized findings with GuardDuty product subscription

Observability

  • CloudWatch Logs -- Lambda execution logs with configurable retention

Data Flow

  1. GuardDuty detector continuously monitors AWS account activity across all enabled protection plans
  2. When a threat is detected, GuardDuty generates a finding and publishes to EventBridge
  3. EventBridge rule matches "GuardDuty Finding" events and routes to two targets
  4. SNS target receives a formatted alert with severity, title, description, account, region, and type
  5. AI Triage Lambda receives the raw finding, invokes Bedrock Claude 3 for analysis
  6. Bedrock returns an AI-enriched assessment (risk evaluation, recommended remediation)
  7. Lambda publishes the enriched analysis to the same SNS topic for unified alerting
  8. GuardDuty exports findings to S3 via the publishing destination
  9. S3 lifecycle transitions findings to Glacier after the configured retention period
  10. Security Hub aggregates GuardDuty findings for compliance and posture dashboards

Industry Adaptation

Enterprise Security Operations

Enable all protection plans and AI triage. Subscribe PagerDuty/Slack to SNS for immediate incident response. Use custom filters to reduce alert fatigue on known benign patterns. Enable Security Hub for compliance dashboards.

Financial Services

Enable RDS protection for database login monitoring. Set finding_publishing_frequency to FIFTEEN_MINUTES. Archive to Glacier for long-term regulatory retention. Use multi-account for organizational coverage.

Healthcare / HIPAA

Enable S3 and Lambda protection for PHI data access monitoring. Use AI triage to prioritize findings related to data exfiltration. Ensure findings S3 bucket has strict access controls and audit logging.

Startups / Cost-Conscious

Start with core GuardDuty (free tier for 30 days). Disable AI triage initially (set enable_ai_triage = false). Enable protection plans incrementally. Use SNS email for simple alerting.

Production Readiness Checklist

  • Confirm GuardDuty is not already enabled in the target account/region
  • Enable Bedrock model access for the AI triage model (if using AI triage)
  • Subscribe alerting endpoints (email, PagerDuty, Slack) to the SNS topic
  • Generate a test finding: aws guardduty create-sample-findings
  • Verify AI triage Lambda executes and enriched alerts arrive via SNS
  • Review and tune custom filter criteria for your environment
  • Invite all member accounts for multi-account coverage
  • Verify Security Hub is receiving GuardDuty findings
  • Set up Glacier lifecycle policy review schedule
  • Configure remote Terraform state backend (S3 + DynamoDB)
  • Tag all resources with Environment, Team, ManagedBy
